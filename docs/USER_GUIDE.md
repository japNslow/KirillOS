## 1. Что такое KirillOS

KirillOS — небольшая учебная 32-битная операционная система для процессоров x86. Она загружается собственным загрузчиком **kboot**, работает в защищённом режиме процессора и общается с оборудованием напрямую, без BIOS:

| Устройство | Что умеет KirillOS |
| :--- | :--- |
| Экран | Текстовый режим 80×25, 16 цветов; графический режим 320×200, 256 цветов |
| Клавиатура и мышь | PS/2, английская раскладка US-QWERTY |
| Жёсткий диск | IDE/ATA, хранение файлов между перезапусками |
| Звук | PC Speaker и звуковая карта Intel AC'97 |
| Часы | Аппаратные часы CMOS RTC |
| Сеть | Сетевая карта Intel e1000: DHCP, ping, DNS, проверка TCP-порта |

Всё управление — с клавиатуры в командной строке. Графические программы (Kirill Commander, Kaint, KGUI) работают и с мышью.

> ⚠️ KirillOS — учебный проект. В ней нет защиты памяти, многозадачности и пользователей: любая программа работает с полными правами, и ошибка в программе может «повесить» всю систему. Перезапуск машины всё исправляет, файлы на диске сохраняются.

## 2. Сборка и первый запуск

### 2.1 Что нужно установить

| Инструмент | Зачем | Где `build.bat` ищет его в первую очередь |
| :--- | :--- | :--- |
| `i686-elf-gcc`, `i686-elf-ld` | Кросс-компилятор C для x86 | `C:\i686\bin\`, затем `PATH` |
| `nasm` | Ассемблер для загрузчика | `C:\nasm\nasm.exe`, затем `PATH` |
| `python` 3.x | Сборка образа диска | `C:\Program Files\Python310\`, затем `PATH` |
| `qemu-system-x86_64` | Эмулятор, в котором запускается система | `C:\msys64\ucrt64\bin\`, затем `PATH` |

### 2.2 Сборка и запуск одной командой

В папке проекта выполните:

```cmd
build.bat
```

Скрипт:
1. собирает загрузчик kboot (сектор MBR и вторую стадию);
2. собирает встроенные игры из папки `apps/`;
3. компилирует и линкует ядро `kernel.bin`;
4. записывает всё в образ диска `kirillos.img` (64 МБ);
5. запускает QEMU с диском, звуком AC'97 и сетевой картой e1000.

Если что-то пошло не так, скрипт напишет `*** BUILD FAILED ***` и остановится.

### 2.3 Как QEMU запускает систему

`build.bat` запускает QEMU так:

```cmd
qemu-system-x86_64 -drive file=kirillos.img,format=raw,if=ide ^
    -audiodev driver=dsound,id=kirillos_audio,out.buffer-length=100000 ^
    -machine pcspk-audiodev=kirillos_audio -device AC97,audiodev=kirillos_audio ^
    -nic user,model=e1000 -m 128M
```

| Параметр | Значение |
| :--- | :--- |
| `-drive ...if=ide` | Образ подключается как жёсткий диск IDE: на нём хранятся файлы |
| `-audiodev` / `-device AC97` | Звук через звуковую систему Windows (DirectSound) |
| `-nic user,model=e1000` | Сетевая карта e1000 с выходом в интернет через NAT QEMU |
| `-m 128M` | 128 МБ оперативной памяти |

Полезные дополнительные параметры:
- `-snapshot` — запуск «на пробу»: все изменения на диске забудутся после выхода из QEMU;
- `-nic none` — запуск без сети.

### 2.4 Образ диска и ваши файлы

Файлы, созданные в KirillOS, хранятся внутри `kirillos.img`. При повторной сборке `create_image.py` **не пересоздаёт** образ, а только обновляет загрузчик и ядро в начале диска, так что ваши файлы переживают пересборку.

Чтобы начать «с чистого листа», удалите `kirillos.img` перед сборкой либо выполните в KirillOS команду `format`.

## 3. Загрузчик kboot

После включения машины BIOS загружает первую стадию kboot (сектор MBR). Она читает с диска вторую стадию и ядро, переводит процессор в 32-битный режим и показывает приглашение:

```text
===============================================================================
                       KirillOS Bootloader (kboot v1.0)
         32-bit Protected Mode | Hardware Interrupts: IRQ1 (PIC/IDT)
===============================================================================
Type 'help' for commands. Type 'boot' to start KirillOS.

kboot>
```

**Чтобы запустить KirillOS, введите `boot` и нажмите Enter.**

### Команды kboot

| Команда | Что делает |
| :--- | :--- |
| `boot` | Загружает ядро KirillOS в память и передаёт ему управление |
| `info` | Состояние загрузчика: режим процессора, линия A20, прерывания, сколько раз сработала клавиатура |
| `clear` | Очищает экран |
| `beep` | Проверка PC Speaker: короткий звуковой сигнал |
| `reboot` | Перезагрузка компьютера |
| `echo ТЕКСТ` | Печатает текст |
| `about` | Информация о kboot |
| `help` | Список команд |

Подробно устройство загрузчика описано в [KBOOT.md](KBOOT.md).

## 4. Загрузка ядра: как читать лог

После `boot` ядро печатает подробный лог инициализации. Каждая строка начинается с метки подсистемы в квадратных скобках, в конце — `OK` (зелёным) или `FAIL` (красным).

| Метка | Что проверяется |
| :--- | :--- |
| `[KirillBoot]` | Ранний старт ядра: стек, проверка сигнатуры Multiboot |
| `[cpu]` | Защищённый режим и регистр флагов процессора |
| `[mboot]` | Данные от загрузчика, объём памяти |
| `[vga]` | Текстовый видеорежим |
| `[8042]` | Контроллер клавиатуры |
| `[pci]` | Список устройств на шине PCI |
| `[ata]` | Жёсткий диск. `FAIL` значит, что диска нет и файлы будут храниться только в памяти |
| `[kfs]` | Файловая система: сколько слотов из 16 занято |
| `[heap]` | Пул памяти ядра (64 КБ) |
| `[pit]` | Системный таймер, 1000 тиков в секунду |
| `[ac97]` | Звуковая карта. Если её нет, звук идёт через PC Speaker |
| `[net]` | Сетевая карта e1000: адрес регистров, MAC-адрес, наличие связи |
| `[dhcp]` | Получение IP-адреса. При успехе — `ip=10.0.2.15 OK` |
| `[init]` | `KirillOS v0.2 all subsystems online` — система готова |

При самой первой загрузке на диск записываются встроенные файлы, а программы на языке K компилируются. Это видно по строкам `[KHEXD] ...`. Затем появляется логотип и приглашение оболочки:

```text
KirillOS>
```

## 5. Командная оболочка

### 5.1 Как вводить команды

- Наберите команду и нажмите **Enter**.
- **Backspace** стирает последний символ.
- Длина строки — до 127 символов.
- Регистр важен: `ls` работает, `LS` — нет.
- Аргументы разделяются пробелами. Кавычек нет: в имени файла не может быть пробела.
- Истории команд, автодополнения по Tab и перемещения курсора стрелками в строке ввода нет.

Если команда не найдена, оболочка ответит красным `Unknown command: ...`.

### 5.2 Самые нужные команды для начала

```text
help              список всех команд
ls                какие файлы есть на диске
cat hello.k       показать содержимое файла
kano notes.txt    открыть текстовый редактор
run snake.bin     запустить игру «Змейка»
play tetris.kmidi сыграть мелодию
kfetch            сведения о системе
```

Полный список — в [разделе 18](#18-полный-справочник-команд).

## 6. Файловая система KirillFS

### 6.1 Как она устроена

KirillFS — простая «плоская» файловая система: папок нет, все файлы лежат в одном списке.

| Параметр | Значение |
| :--- | :--- |
| Максимум файлов | 16 |
| Максимальный размер файла | 48 КБ (49 151 байт) |
| Длина имени | до 23 символов |
| Запрещено в имени | пробел, `/`, `\`, управляющие и не-ASCII символы |
| Где хранится | На жёстком диске начиная с сектора 321 |

При старте вся файловая система читается в память, а каждое изменение сразу записывается на диск. Если диска нет (в логе `[ata] ... FAIL`), KirillFS работает только в памяти, и после перезагрузки файлы пропадут.

Расширение файла — просто часть имени, но программы смотрят на него:

| Расширение | Что это | Чем открывается |
| :--- | :--- | :--- |
| `.txt` и любые другие | Текст | `cat`, `kano` |
| `.k` | Исходный код на языке K | `kano`, `khexd build` |
| `.ko` | Объектный файл K | `khexd link` |
| `.khex` | Программа для виртуальной машины KHEX | `run`, `khex` |
| `.bin` | Программа в машинном коде x86 | `run`, `khex` |
| `.kmidi` | Мелодия | `play`, `kmidi` |
| `.bmp` | Картинка 256 цветов | `kaint`, обои KGUI |

### 6.2 Встроенные файлы

При первой загрузке система создаёт:

| Файл | Что это |
| :--- | :--- |
| `tetris.kmidi`, `mario.kmidi`, `demo.kmidi` | Мелодии: Тетрис, Super Mario, демо-чиптюн |
| `snake.bin`, `guess.bin`, `matrix.bin` | Игры «Змейка», «Угадай число» и эффект «Матрица» |
| `hello.k`, `clicker.k` | Примеры программ на языке K |
| `hello.khex`, `clicker.khex` (и `.ko`) | Те же примеры, уже скомпилированные |
| `demo.bmp` | Картинка для Kaint и обоев рабочего стола |

Это 13 файлов из 16, поэтому свободных слотов всего 3. Ненужное удаляйте командой `rm`: например, промежуточные `hello.ko` и `clicker.ko` для запуска не нужны.

### 6.3 Команды

| Команда | Что делает |
| :--- | :--- |
| `ls` | Список файлов и их размеры в байтах |
| `touch ИМЯ` | Создаёт пустой файл |
| `write ИМЯ ТЕКСТ` | Записывает текст в **существующий** файл, заменяя старое содержимое |
| `cat ИМЯ` | Выводит содержимое файла на экран |
| `rm ИМЯ` | Удаляет файл |
| `format` | Удаляет **все** файлы (без подтверждения!) |
| `fsinfo` | Ограничения файловой системы и где она хранится |

Пример:

```text
KirillOS> touch hello.txt
KirillOS> write hello.txt Privet iz KirillOS!
KirillOS> cat hello.txt
Privet iz KirillOS!
KirillOS> rm hello.txt
```

> 💡 `write` не создаёт файл. Если файла нет, будет ошибка `File not found` — сначала выполните `touch`. Редакторы `kano` и `kdhe` создают файл сами.

### 6.4 Сообщения об ошибках

| Сообщение | Причина |
| :--- | :--- |
| `File not found` | Файла с таким именем нет. Проверьте `ls` и регистр букв |
| `File already exists` | `touch` для файла, который уже есть |
| `KirillFS: no free file slots` | Заняты все 16 слотов — удалите что-нибудь |
| `Invalid file name` | Пустое имя, слишком длинное или с запрещёнными символами |
| `File is too large (max 48 KB)` | Данные не помещаются в один файл |

## 7. Текстовый редактор Kano

Kano — клон редактора GNU nano.

```text
kano ИМЯ_ФАЙЛА
```

Если файла нет, Kano создаст его (в строке состояния появится `[ New File ]`).

### 7.1 Экран

```text
 KANO 0.2              File: notes.txt                  [Modified]   ← заголовок
текст файла...                                                        ← 21 строка текста
...
[ Read 3 lines (42 bytes) ]                                           ← строка состояния
^G Get Help   ^O WriteOut   ^W Where Is   ^K Cut Line   ^C Cur Pos    ← подсказки
^X Exit       ^R Read File  ^U Paste      ^\ Go To Line ^S QuickSave
```

`[Modified]` означает, что есть несохранённые изменения. Мигающий курсор стоит там, где будет вставлен символ.

### 7.2 Клавиши

| Клавиша | Действие |
| :--- | :--- |
| Буквы, цифры, знаки | Вставка символа |
| **Enter** | Новая строка |
| **Tab** | Вставляет пробелы до следующей позиции, кратной 4 |
| **Backspace** | Удалить символ слева от курсора |
| **Delete** | Удалить символ под курсором |
| **← → ↑ ↓** | Перемещение курсора |
| **Home** / **Ctrl+A** | В начало строки |
| **End** / **Ctrl+E** | В конец строки |
| **PageUp** / **PageDown** | На 21 строку вверх / вниз |
| **Ctrl+O** / **Ctrl+S** | Сохранить файл |
| **Ctrl+X** / **Ctrl+Q** / **Esc** | Выйти. Если есть изменения, Kano спросит: `(Y)es` — сохранить, `(N)o` — выйти без сохранения, `(C)ancel` — вернуться |
| **Ctrl+K** | Вырезать текущую строку |
| **Ctrl+U** | Вставить вырезанную строку |
| **Ctrl+W** | Поиск текста (без учёта регистра). Enter — искать, Esc — отмена |
| **Ctrl+\\** | Перейти к строке с номером |
| **Ctrl+C** | Показать номер строки, столбца и процент от файла |
| **Ctrl+R** | Вставить в текст содержимое другого файла |
| **Ctrl+G** | Справка по клавишам (любая клавиша — назад) |

Максимальный размер текста — 48 КБ. Русские буквы ввести нельзя: клавиатура работает только в английской раскладке.

## 8. Hex-редактор Kdhe

Kdhe показывает и правит файл побайтно: слева шестнадцатеричные значения, справа те же байты как символы ASCII.

```text
kdhe ИМЯ_ФАЙЛА        открыть файл (если его нет — создать пустой)
kdhe disk НОМЕР       открыть сектор жёсткого диска (512 байт) по номеру LBA
```

### 8.1 Клавиши

| Клавиша | Действие |
| :--- | :--- |
| **← → ↑ ↓** | Перемещение по байтам |
| **Home** / **End** | В начало / конец строки |
| **PageUp** / **PageDown** | Прокрутка на страницу |
| **Tab** | Переключение между вводом HEX (цифры `0-9`, `A-F`) и ASCII (обычные символы) |
| **Insert** | Вставить байт в позицию курсора |
| **Delete** | Удалить байт под курсором |
| **Backspace** | Удалить байт перед курсором |
| **Ctrl+S** | Сохранить |
| **Ctrl+Q** / **Esc** | Выйти. При несохранённых изменениях: **Ctrl+S** — сохранить, **Ctrl+Q** или **Esc** ещё раз — выйти без сохранения |

В режиме HEX байт набирается двумя цифрами: первая задаёт старшую половину, вторая — младшую. В файловом режиме размер ограничен 2048 байтами.

### 8.2 Режим диска — осторожно

`kdhe disk N` правит сектор жёсткого диска напрямую, в обход файловой системы. **Ctrl+S сразу записывает сектор на диск.**

| Сектора | Что там лежит |
| :--- | :--- |
| 0 | MBR: первая стадия загрузчика |
| 1–64 | Вторая стадия загрузчика kboot |
| 65–320 | Ядро KirillOS |
| 321 | Служебный сектор KirillFS (сигнатура `KFS4`) |
| 322 | Таблица файлов KirillFS |
| 323 и дальше | Данные файлов: по 96 секторов на каждый слот |

Неосторожная запись в сектора 0–320 сломает загрузку (лечится пересборкой `build.bat`), а в 321 и дальше — испортит файлы. Смотреть сектора безопасно.

Пример ручной сборки программы в Kdhe по байтам разобран в [BYTECODE_AND_VM.md](BYTECODE_AND_VM.md).

## 9. Звук и музыкальный трекер Kmidi

### 9.1 Простые звуковые команды

| Команда | Что делает |
| :--- | :--- |
| `beep` | Короткий сигнал 880 Гц |
| `tone ЧАСТОТА МС` | Звук заданной частоты (Гц) и длительности (мс), например `tone 440 500` |
| `music` | Встроенная демо-мелодия |
| `play ФАЙЛ.kmidi` | Проиграть мелодию из файла |

Если в системе есть звуковая карта AC'97 (в логе `[ac97] ... OK`), звук идёт через неё, иначе — через PC Speaker.

### 9.2 Трекер Kmidi

```text
kmidi ИМЯ.kmidi      (или kidi ИМЯ.kmidi)
```

Kmidi показывает мелодию как таблицу шагов: номер, нота, частота, длительность и полоску длительности. Сверху — клавиатура фортепиано, на которой подсвечивается играющая нота.

| Клавиша | Действие |
| :--- | :--- |
| **↑ / ↓** | Выбор шага. Ниже последнего шага есть строка `[ADD NEW NOTE]` — добавление в конец |
| **Пробел** | Проиграть всю мелодию (Пробел или Esc — остановить) |
| **Enter** | Проиграть выбранный шаг |
| Клавиши-ноты (таблица ниже) | Заменить ноту в выбранном шаге, а на строке `[ADD NEW NOTE]` — добавить новую |
| **R** | Сделать шаг паузой (`REST`) или добавить паузу в конец |
| **+** / **-** | Длительность шага ±50 мс (от 50 до 2000 мс) |
| **Insert** | Вставить перед выбранным шагом новый шаг `A4` на 200 мс |
| **Delete** | Удалить выбранный шаг |
| **Backspace** | Удалить выбранный шаг, а на строке `[ADD NEW NOTE]` — последний шаг |
| **Ctrl+S** | Сохранить |
| **Ctrl+Q** / **Esc** | Выйти (с вопросом о сохранении, если есть изменения) |

**Раскладка нот** — как на фортепиано: нижний ряд клавиатуры — малая октава, верхний — первая.

| Клавиша | Нота | Клавиша | Нота | Клавиша | Нота |
| :---: | :---: | :---: | :---: | :---: | :---: |
| Z | C3 | Q | C4 | I | C5 |
| S | C#3 | 2 | C#4 | 9 | D5 |
| X | D3 | W | D4 | O | E5 |
| D | D#3 | 3 | D#4 | P | G5 |
| C | E3 | E | E4 | | |
| V | F3 | R* | F4 | | |
| G | F#3 | 5 | F#4 | | |
| B | G3 | T | G4 | | |
| H | G#3 | 6 | G#4 | | |
| N | A3 | Y | A4 | | |
| J | A#3 | 7 | A#4 | | |
| M | B3 | U | B4 | | |

\* В редакторе трекера клавиша **R** занята под паузу, поэтому ноту F4 удобнее записывать вручную в файле.

### 9.3 Формат файла `.kmidi`

Это обычный текст: ноты через пробел, у каждой — длительность в миллисекундах после двоеточия.

```text
E5:250 B4:125 C5:125 D5:250 REST:125 A4:250
```

- Название ноты: буква `A`–`G`, при необходимости `#`, затем номер октавы: `C4`, `F#3`, `A#4`.
- `REST` — пауза.
- Если длительность не указана, берётся 200 мс.

Мелодию можно написать прямо в Kano:

```text
KirillOS> kano my.kmidi
   (вводим: C4:200 E4:200 G4:200 C5:400, сохраняем Ctrl+O, выходим Ctrl+X)
KirillOS> play my.kmidi
```

## 11. Программирование на языке K

K — простой язык, программы на котором пишутся и компилируются прямо внутри KirillOS. Полное описание языка — в [K_LANGUAGE.md](K_LANGUAGE.md).

### 11.1 Первая программа за 3 шага

**1. Напишите программу в Kano:**

```text

```

```rust
fn main() {
    clear()
    color(10, 0)
    print("Hello from K!\n")
    var n = rand(100)
    print("Random: ")
    print(n)
    print("\nPress any key...")

}
```

Сохраните (**Ctrl+O**) и выйдите (**Ctrl+X**).

**2. Скомпилируйте:**

```text
KirillOS> khexd build hi.k
```

Получится `hi.khex` (и промежуточный `hi.ko`).

**3. Запустите:**

```text
KirillOS> run hi.khex
```

### 11.2 Команды компилятора KHEXD

| Команда | Что делает |
| :--- | :--- |
| `khexd build ИСХОДНИК.k [ПРОГРАММА.khex]` | Компиляция и линковка за один шаг |
| `khexd compile ИСХОДНИК.k [ОБЪЕКТ.ko]` | Только компиляция в объектный файл |
| `khexd link ОБЪЕКТ.ko [ПРОГРАММА.khex]` | Только линковка |
| `khexd` | Краткая справка |

Если имя результата не указано, берётся имя исходника с новым расширением.

### 11.3 Коротко о языке

| Возможность | Пример |
| :--- | :--- |
| Точка входа | `fn main() { ... }` |
| Переменные (целые числа) | `var x = 5` |
| Арифметика и сравнения | `+ - * / %`, `== != < > <= >=` |
| Условие | `if (x > 3) { ... }` |
| Цикл | `while (x < 10) { ... }`, выход — `break` |
| Вывод | `print("текст")`, `print(x)`, `clear()`, `color(fg, bg)`, `cursor(row, col)` |

## 14. Графический редактор Kaint

```text
kaint             новая картинка
kaint demo.bmp    открыть картинку   (вместо kaint можно писать paint)
```

Kaint — «Paint» для KirillOS: холст 240×150 пикселей, 256 цветов, сохранение в формате BMP.

### 14.1 Экран

- **Сверху** — имя файла, текущий инструмент и координаты курсора.
- **Слева** — панель инструментов.
- **Снизу** — палитра цветов, текущий основной цвет (FG) и дополнительный цвет, строка состояния.
- **В центре** — холст.

### 14.2 Инструменты

| Клавиша | Инструмент | Как пользоваться |
| :---: | :--- | :--- |
| **P** | Карандаш (Pencil) | Рисование тонкой линией при зажатой кнопке мыши |
| **B** | Кисть (Brush) | То же, толще |
| **L** | Линия (Line) | Зажать в начале, отпустить в конце |
| **R** | Прямоугольник (Rect) | Тянуть от угла до угла |
| **F** | Закрашенный прямоугольник (FRect) | Тянуть от угла до угла |
| **C** | Окружность (Circle) | Тянуть от центра |
| **O** | Закрашенный круг (FCirc) | Тянуть от центра |
| **K** | Заливка (Bucket) | Щелчок заливает область одного цвета |
| **T** | Текст (Text) | Щелчок по холсту, ввод текста, **Enter** или **Esc** — закончить |
| **E** | Ластик (Eraser) | Стирает дополнительным цветом |
| **I** | Пипетка (Picker) | Щелчок берёт цвет с холста и возвращает карандаш |

Инструмент можно выбрать и щелчком по кнопке на панели слева.

### 14.3 Цвета

- **Левый щелчок** по палитре — основной цвет (им рисуют).
- **Правый щелчок** по палитре — дополнительный цвет (им работает ластик и заливается новый холст).
- Рисование правой кнопкой мыши рисует дополнительным цветом.
- Пипетка левой кнопкой берёт основной цвет, правой — дополнительный.
- Ластик всегда стирает дополнительным цветом (по умолчанию белым).

### 14.4 Файлы

| Клавиша | Действие |
| :---: | :--- |
| **S** | Сохранить в BMP: введите имя, **Enter** — сохранить, **Esc** — отмена |
| **N** | Новый холст, залитый дополнительным цветом |
| **Q** / **Esc** | Выход в оболочку |

Сохранять и открывать файлы можно и кнопками на панели. Учтите ограничение размера файла 48 КБ: картинка 240×150 в формате BMP с палитрой в него помещается.

## 16. Сеть

### 16.1 Подключение

KirillOS работает с сетевой картой **Intel e1000** — её QEMU эмулирует по умолчанию, и `build.bat` подключает её параметром `-nic user,model=e1000`. При загрузке система сама получает IP-адрес по DHCP:

```text
[net] e1000 mmio=0xFEBC0000 mac=52:54:00:12:34:56 OK
[dhcp] ip=10.0.2.15 OK
```

В режиме `-nic user` QEMU создаёт виртуальную сеть:

| Адрес | Что это |
| :--- | :--- |
| `10.0.2.15` | KirillOS |
| `10.0.2.2` | Шлюз (виртуальный роутер QEMU). Подключения к нему уходят на сам компьютер-хост |
| `10.0.2.3` | DNS-сервер (запросы пересылаются DNS хоста) |

### 16.2 Команды

| Команда | Что делает |
| :--- | :--- |
| `ifconfig` / `net` | MAC, IP, маска, шлюз, DNS, связь и счётчики принятых/отправленных кадров |
| `dhcp` | Получить IP-адрес заново |
| `ping ХОСТ [N]` | Отправить N эхо-запросов ICMP (по умолчанию 4) |
| `tcping ХОСТ [ПОРТ] [N]` | Проверить TCP-порт (по умолчанию 80): `Connected` — порт открыт, `Port closed (RST)` — закрыт, `Timed out` — нет ответа |
| `host ИМЯ` / `nslookup ИМЯ` | Узнать IP-адрес по имени через DNS |

`ХОСТ` — IP-адрес (`8.8.8.8`) или имя (`example.com`). `ping` и `tcping` можно прервать клавишей **Esc**.

```text
KirillOS> host example.com
example.com has address 104.20.23.154
KirillOS> tcping example.com 80 2
TCPING 104.20.23.154:80 (ESC to stop)
Connected: seq=1 time=12 ms
Connected: seq=2 time=11 ms
--- 2 of 2 answered ---
```

### 16.3 Важно про ping в QEMU

В режиме `-nic user` QEMU не может отправлять настоящие ICMP-пакеты с Windows и **отвечает на ping сам**, за любой адрес — даже несуществующий. Поэтому `ping` до внешних адресов всегда «успешен» и показывает 0–1 мс и TTL 255. Для проверки реальной доступности используйте:
- `host ИМЯ` — DNS-запрос действительно уходит в интернет;
- `tcping` — QEMU отвечает гостю только после того, как хост реально установил TCP-соединение.

Если на хосте работает VPN в режиме TUN (например, sing-box) или прозрачный прокси, он сам принимает любые TCP-соединения, и `tcping` тоже покажет «успех» для любого адреса. Чтобы проверить сеть по-настоящему, исключите QEMU из туннеля или временно выключите VPN.

### 16.4 Запуск без сети

Если запустить QEMU с `-nic none`, в логе будет `[net] no e1000 NIC, networking disabled`, а сетевые команды подскажут, как подключить карту. Остальная система работает как обычно.

## 19. Решение проблем

| Проблема | Что делать |
| :--- | :--- |
| `Unknown command: ...` | Проверьте написание и регистр (`ls`, а не `LS`). Список — `help` |
| `File not found` при `write` | `write` пишет только в существующий файл: сначала `touch ИМЯ` |
| `KirillFS: no free file slots` | Все 16 слотов заняты: удалите ненужное (`rm temp.khex`, `rm hello.ko`) |
| После перезапуска файлы пропали | В логе `[ata] ... FAIL`: диск не подключён, файлы хранились только в памяти. Запускайте QEMU с `-drive file=kirillos.img,format=raw,if=ide`. Также проверьте, не запущен ли QEMU с `-snapshot` |
| Хочу вернуть систему к исходному состоянию | Удалите `kirillos.img` и выполните `build.bat`, либо `format` и перезагрузка — встроенные файлы создадутся заново |
| Нет звука | Проверьте `[ac97]` в логе и параметры `-audiodev` / `-device AC97`. Без AC'97 звук идёт через PC Speaker |
| Мышь не работает в графических программах | Щёлкните в окно QEMU, чтобы оно захватило мышь. Отпустить мышь — **Ctrl+Alt+G** |
| `[net] no e1000 NIC` | QEMU запущен без сетевой карты: добавьте `-nic user,model=e1000` |
| `net: no IP address, run 'dhcp' first` | Выполните `dhcp`. Если ответа нет — проверьте сеть QEMU |
| `ping` отвечает за 0 мс от любого адреса | Это ответы самого QEMU, см. [раздел 16.3](#163-важно-про-ping-в-qemu) |
| Не вводятся русские буквы | Поддерживается только английская раскладка US-QWERTY |
| Программа зависла | Перезапустите машину (в QEMU: меню Machine → Reset). Сохранённые файлы останутся |
| Не загружается после `kdhe disk` | Вы записали что-то в сектора загрузчика или ядра: выполните `build.bat`, он перезапишет их, не трогая файлы |
| `build.bat`: `i686-elf-gcc not found` | Установите кросс-компилятор в `C:\i686\bin\` или добавьте его в `PATH` |
| `create_image.py`: `kernel.bin ... exceeds 131072 limit` | Ядро больше 128 КБ — столько читает загрузчик. Нужно уменьшать ядро или расширять область ядра на диске |

## 20. Ограничения системы

| Что | Ограничение |
| :--- | :--- |
| Процессор | 32-битный x86, одно ядро, без многозадачности |
| Защита | Нет защиты памяти: программы работают с правами ядра |
| Память | Пул ядра 64 КБ (память не освобождается) |
| Файлы | 16 файлов, до 48 КБ каждый, без папок |
| Ядро | До 128 КБ на диске |
| Строка команды | До 127 символов, без истории |
| Клавиатура | Только английская раскладка |
| Экран | Текст 80×25 или графика 320×200 |
| Сеть | Только IPv4, без TCP-передачи данных (только проверка соединения), без прерываний |
| Язык K | Только целые числа, до 32 переменных, вся программа — одна функция `main` |
